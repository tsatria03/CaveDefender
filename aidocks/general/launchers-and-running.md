There is **no test suite and no linter** — running is scripted by the Python launchers in `cf/<side>/`, and compiling/packaging/releasing by `build/tools.py`, but it's otherwise manual, on purpose. The launchers hard-code `C:\nvgt\nvgt.exe`; `build/tools.py` reads the engine path from `~/.game_tools/tools.ini` (pointed at the same nvgt build — see [[engine-pinned-legacy-nvgt]]). All need Python 3.12 installed (per-user, at `AppData\Local\Programs\Python\Python312`; it is the only Python on the machine since the accidental Chocolatey 3.15 was removed 2026-11-24), and double-clicking a `.py` launcher relies on the per-user `.py` association to the py launcher (`AppData\Local\Programs\Python\Launcher\py.exe`) — the Python installer's "py launcher" + "Associate files with Python" options must stay ticked. Each launcher runs the `src/<side>` script with cwd set to its own `cf/<side>` folder so assets resolve (see [[path-conventions]]).

- **Client:** `cf/client/cfc.py` runs `src/client/cfc.nvgt` (cwd `cf/client`). It launches `nvgt.exe` with `CREATE_NO_WINDOW` (no console) and its stdout/stderr captured to a temp log, then **watches for `COMPILE_WAIT` seconds (default 5)**: a failed compile exits fast with a non-zero code, so the launcher writes the captured output to **`errors.txt`** in the directory cfc.py was launched from (plus a popup) — since the windowless client otherwise swallows compile errors; a clean compile keeps running, so the launcher detaches and leaves it (deleting the temp log / any stale `errors.txt`). The launcher hides its own console at startup (ctypes `ShowWindow`), so the `COMPILE_WAIT` watch runs invisibly in the background — the client's own NVGT game window opens right away with **no lingering cmd window**, and an absent/empty `errors.txt` means "no compile errors". (Server differs — its launcher keeps the console open, so it shows compile errors live and needs none of this.) `main()` installs the keyhook, gates on `SCREEN_READER_AVAILABLE` / `SOUND_AVAILABLE`, blocks a second instance via `gamstence.is_already_running`, creates the message buffers, reads prefs, sets up the network client, then loops `mainmenu()`.
- **Server:** `cf/server/cfs.py` runs the **downcheck supervisor** (`src/server/downcheck.nvgt`, cwd `cf/server`) with blocking `subprocess.run`, so its console window stays open the whole session; downcheck launches `src/server/cfs.nvgt` and relaunches it after a restart command or crash. Both NVGT windows are hidden when interpreted (downcheck always hides its own; cfs.nvgt hides its titled window when `!SCRIPT_COMPILED`), so in dev the console from cfs.py is the only visible window, by design (dev confirmed 2026-11-24: leave it hidden). The legacy engine has NO print/console output function, so the server cannot write status lines there. The server loads config from `data/host/main/conf.svr` and the MOTD from `data/host/main/motd.svr`, ensures the `data/` folders exist, calls `net.setup_server()`, sets a `show_game_window` title (version/port/user-limit) then hides that NVGT window with `if(!SCRIPT_COMPILED) hide_window()` (interpreted = headless, the cmd window is the UI; a compiled build keeps the window), then loops `netloop()` + `gametick()`. **Compile check (added 2026-11-25 at the dev's request, matching the client's errors.txt):** before starting downcheck, cfs.py runs `nvgt -c -q cfs.nvgt` in src/server (capturing its output), then deletes the throwaway src/server/cfs build folder it makes (only if it wasn't already there). On failure it writes the same tidied report to errors.txt in the folder cfs.py was launched from, prints where, waits for Enter and exits without starting downcheck (which would otherwise relaunch a broken server over and over). A clean launch removes any stale errors.txt first. This adds roughly a second or two to every server start.
- **Build a release:** `build/tools.py` (launched by `build/tools.bat`, which runs `py -3.12 tools.py`, falling back to `%LOCALAPPDATA%\Programs\Python\Launcher\py.exe` when py isn't on PATH; or run with flag args non-interactively — the CLI takes **4** flags `<skip_compile> <skip_package> <skip_release> <skip_empty_release>`, each 0 ask / 1 run / 2 skip silently; the menu is 1-10: commit helpers 1-5, then 6 Full release, 7 Compile only, 8 Package only, 9 Release only, 10 Exit) is the unified pipeline that replaced the old per-side `cfcm.py`/`cfsm.py`. Its **compile** step does both sides in turn: it first mirrors `build/version.txt` into both `src/<side>/includes/version.nvgt`, then runs `nvgt -c` from each `src/<side>` (bundle lands there), copies that side's assets from `cf/<side>/` into the bundle as ordinary loose folders (client: `lib,sounds,docks,data`; server: `data,docks,sounds`), and moves it to `release/windows/CaveDefender<Side>_password_is_<pw>/<cfc|cfs>`. **Server security scrub:** after the server bundle is assembled, `sanitize_server_bundle(SERVER_BUILD)` strips private/host-specific data from the shipped bundle so the itch.io archive is a clean slate: (1) empties `data/host/game/players` (removes every account — passwords/emails/records — but keeps the empty folder), (2) blanks the `owners=` line in `conf.svr` (so no username ships pre-trusted as owner — else whoever registered that name on the new server would become owner; the host sets their own), (3) deletes `reports.svr` + `feedback.svr` (private player-submitted logs — reports name players, feedback carries names + messages) and `peak.svr` (this server's peak-players stat) if present, and (4) overwrites `motd.svr` with the neutral default `Welcome to CaveDefender. We hope you enjoy your stay here.` (no trailing newline — the whole file is the MOTD). Warnings need no handling: they live per-account in `data/host/game/players/<name>/warnings.usr`, already gone with (1). Bundle copy ONLY — the source under `cf/server` is never touched (verified: source `conf.svr` keeps `owners=tsatria03,tony`, source `motd.svr`/`peak.svr` unchanged). The host's server recreates/repopulates all of this on its own. Note `conf.svr` uses LF endings; the scrub preserves each line's ending. Full `host/main` inventory: KEEP conf/chatfilter/languages/pronouns (config); SCRUB reports/feedback/peak; RESET motd to the default welcome. **Package** makes two password-protected `.7z` archives (client + server) in `release/archives/`; **release** attaches both to a GitHub release. (SimpleFighter's website-update step was removed — CaveDefender isn't published on the site.) The engine/7-Zip/gh paths come from `~/.game_tools/tools.ini` (shared across the legacy-engine games), the per-repo config from `build/tools.ini`. There is **no boxing stage** any more: Enigma Virtual Box was removed 2026-11-24 ([[build-tools-remove-boxing]]; history in [[enigma-boxing]]), so the order is compile, package, release.

Remember [[dont-compile-yourself]]: never run the launchers/compilers; the dev builds and verifies.

**How the dev tests (dev, 2026-11-25):** "I always run the .py file, aka the .nvgt script that python launches. I never compile the game. Unless I'm ready to release it." So every test is a source run through cfc.py / cfs.py (interpreted, SCRIPT_COMPILED false, cwd cf/<side>). Anything that only happens in a compiled build (SCRIPT_COMPILED branches, bundle-only paths, the offline server code built into cfc.exe) goes untested until a release build, so flag it plainly when a change depends on that. "Restart the client/server" means rerun the .py.

**Client startup compiles the offline server (2026-11-26, [[offline-mode]]):** cfc.nvgt's half-second pause before the main menu now times offline_build() and waits only the rest of the 500 ms, so the offline module is ready before the player picks offline (startup is no slower while that compile stays under 500 ms). A failed build stays silent there and is reported when offline is chosen.
